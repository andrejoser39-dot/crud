Actualizar una tarea: Se pueden usar dos opciones dependiendo del alcance:

PUT: Si vas a reemplazar toda la tarea por una nueva versión.

PATCH: Si solo vas a modificar un atributo específico (por ejemplo, cambiar solo el nombre o solo el estado de "completado"). Para este ejercicio, PATCH suele ser el más eficiente.


2. ¿Qué información necesitarían enviar al servidor para actualizar o eliminar una area?
Para que el servidor sepa exactamente qué elemento modificar o borrar, se necesita lo siguiente:

Para Eliminar (DELETE):

El ID de la tarea: Se envía generalmente en la URL (por ejemplo: https://jsonplaceholder.typicode.com/todos/5, donde 5 es el ID). No se suele requerir un cuerpo (body) en la petición.

Para Actualizar (PATCH / PUT):

El ID de la tarea: Indispensable en la URL para saber cuál actualizar.

El Cuerpo de la petición (Body): Un objeto JSON con los nuevos datos. Si usas PATCH para cambiar el nombre, solo envías { "title": "Nuevo nombre" }. Si usas PUT, deberías enviar el objeto completo { "id": 5, "title": "Nuevo nombre", "completed": false, "userId": 1 }.



3. ¿En qué momento debe actualizarse el DOM?
El DOM (la interfaz visual que ve el usuario en el navegador) debe actualizarse únicamente después de recibir una respuesta exitosa (HTTP 200, 201, etc.) por parte del servidor.

El flujo correcto es:
El usuario hace clic en un botón (ej. "Eliminar").

Se dispara la petición asíncrona (fetch) al servidor.

Se espera la respuesta.

Si el servidor responde que la operación fue exitosa (response.ok), entonces se modifica el DOM (se borra la fila, se cambia el texto o se agrega la nueva tarea a la lista).
